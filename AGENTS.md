# timeline-project

## Описание проекта и стек
Веб-приложение для визуализации дерева последствий при принятии решений.
Пользователь вводит одно решение, LLM генерирует две ветки-последствия,
от каждого — новая развилка (до 3 уровней). В конце — «карта временной линии».
Эстетика TVA из «Локи»: тёмный фон, золотая линия, синие ветки, ретро-терминал.

Стек: Java 17, Spring Boot 3, Maven, PostgreSQL, Thymeleaf/HTMX (минимальный фронт).
LLM: российский агрегатор (OpenAI-совместимый API), structured output.
Деплой: TimeWeb Cloud (VPS).

Полное описание — `docs/project-description.md`.

## Команды
- Установка: `mvn clean install`
- Запуск: `mvn spring-boot:run`
- Тесты (все): `mvn test`
- Один тест: `mvn test -Dtest=ИмяКласса`
- Линтер: `mvn checkstyle:check`

## Конвенции
- Пакет: `ru.janeforjane.timeline`
- Тесты: JUnit 5, имена `should_..._when_...`
- Коммиты: `feat:`, `fix:`, `docs:`, `chore:` (Conventional Commits)
- Никаких `System.out.println` — только SLF4J
- LLM-вызовы — только через сервисный слой, не из контроллера
- Таймауты на внешние вызовы обязательны

## Правила работы

- Для каждого ДЗ — отдельный бренч `hw/NN-название`, мерж в `main` после сдачи.
- Запрещено коммитить `.env`, `target/`, `application-local.yml` с секретами.
- Перед коммитом `mvn test` должен быть зелёным.


## Ограничения проекта
- Глубина дерева — 3 уровня, ширина — 2 ветки.
- Один LLM-вызов на узел (не «всё дерево сразу»).
- Кэш по хэшу (узел + уровень), лимит вызовов на сессию.
- Fallback: если LLM недоступна — шаблонные ветки по правилам.
