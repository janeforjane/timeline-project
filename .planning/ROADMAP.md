# Roadmap: Timeline Project

## Overview

Пользователь вводит одно решение и получает наглядную карту временной линии. Путь от скелета (заглушка LLM, статическая страница) к полному MVP: реальный LLM-слой, генерирующий ветки последствий → интерактивное дерево (глубина 3, ширина 2) → сохранение в PostgreSQL → карта линии с итогом и история сохранённых линий. Генерация (содержание) и TVA-визуализация (форма) равнозначны на каждом шаге.

## Phase Details

### Phase 1: LLM-слой и ввод решения
**Goal**: Пользователь вводит текст решения и получает две настоящие LLM-сгенерированные ветки-последствия, а при недоступности LLM — шаблонные ветки по правилам.
**Mode**: mvp
**Depends on**: Nothing (first phase)
**Requirements**: INP-01, INP-02, LLM-01, LLM-02, LLM-03, LLM-04, LLM-05, LLM-06
**Success Criteria** (what must be TRUE):
  1. Пользователь вводит текст решения и запускает построение линии кнопкой — приложение возвращает две ветки-последствия в структурированном виде (`{branches: [{consequence, next_dilemma?}]}`)
  2. Пустой или состоящий только из пробелов ввод не отправляется — пользователь видит сообщение об ошибке валидации
  3. Если LLM недоступна или не уложилась в таймаут, пользователь всё равно получает две шаблонные ветки по правилам, а не ошибку сервера
  4. Повторный одинаковый запрос к тому же узлу и уровню не выполняет новый внешний вызов — возвращается кэшированный результат
  5. При превышении лимита LLM-вызовов на сессию пользователь получает понятное сообщение вместо бесконечной генерации

### Phase 2: Дерево последствий
**Goal**: Пользователь видит полное дерево последствий (глубина 3, ширина 2) в TVA-эстетике и управляет ветками через UI — клик по узлу открывает панель и позволяет продолжить ветку.
**Mode**: mvp
**Depends on**: Phase 1
**Requirements**: GRPH-01, GRPH-02, GRPH-03
**Success Criteria** (what must be TRUE):
  1. Пользователь видит дерево глубиной 3 и шириной 2: 1 корень → 2 ветки → 4 последствия → 8 финалов
  2. Клик по узлу открывает панель с текстом последствия и кнопкой «Продолжить эту ветку»
  3. На уровне 3 вместо следующей развилки пользователь видит итог (`final_summary`)

**UI hint**: yes

### Phase 3: Персистентность
**Goal**: Дерево и карта линии сохраняются в PostgreSQL (таблицы `decision`, `node`, `edge`) и восстанавливаются после перезагрузки приложения.
**Mode**: mvp
**Depends on**: Phase 2
**Requirements**: PERS-01, PERS-02
**Success Criteria** (what must be TRUE):
  1. После построения дерева его узлы и рёбра сохраняются в БД (таблицы `decision`, `node`, `edge`)
  2. После перезагрузки приложения ранее построенное дерево и карта восстанавливаются из БД без потери данных
**Plans**: TBD

### Phase 4: Карта линии и история
**Goal**: Пользователь получает сохраняемую карту временной линии с итогом по веткам и может открывать сохранённые линии из истории через UI.
**Mode**: mvp
**Depends on**: Phase 3
**Requirements**: MAP-01, MAP-02, HIST-01, HIST-02
**Success Criteria** (what must be TRUE):
  1. Пользователь получает полную карту линии — сохранённый граф всех веток дерева
  2. На карте отображается итог по веткам (плюсы/минусы)
  3. Пользователь видит список сохранённых линий
  4. Пользователь может открыть любую сохранённую линию повторно
